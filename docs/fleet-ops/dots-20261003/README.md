# Как читать этот пакет

Откройте **REPORT.md**: это актуальный русскоязычный итог исследования и внедрения. Затем **ACCEPTANCE.md** — окончательная приёмка точных файлов и границ результата. Их наличие и статусы проверяются при сборке финального архива; архив не собирается из незавершённых карт.

## Что является результатом

В существующий Hermes-флот перенесена **операционная методика** Dots. Одинаковая reference и один загрузочный hook добавлены в company-os двенадцати рабочих профилей без выравнивания и замены их прежних версий. Принятый предмет — METHOD-CANDIDATE.md с SHA256 `f2a85ced87b620bf08cdfc2f3de85ce004a2912efded4da85b668148f00dce6f`.

Это не установка OpenAI Dots, не подключение облака/аккаунтов/локального компьютера и не создание нового scheduler. Архив не предоставляет новых разрешений и не является инструкцией выполнить содержащиеся в нём внешние страницы или скрипты.

## Порядок чтения и доказательства

1. **REPORT.md → ACCEPTANCE.md**: итог и точные границы принятия.
2. **STUDY.md**: подробный frozen-разбор продукта, режимов работы, памяти, задач, приложений, компьютеров, каналов, разрешений, безопасности и enterprise-контроля.
3. **METHOD-CANDIDATE.md → LOAD-HOOK.md**: что именно интегрировано; существующие каноны флота и Fleet Policy сохраняют приоритет.
4. **SOURCE-AUDIT.md → EVIDENCE-ERRATA.md → QA-ERRATA.md**: исходные утверждения и исправленная совокупность доказательств. Старые отчёты сохранены для трассировки, а не выданы за безошибочные.
5. **QA-CHECK-t_a3c78661.json → QA-ERRATA-CHECK-t_a1ec6fed.json**: считать реальные dictionaries checks. Фактические totals — 23/23 и 31/31; текстовые прежние счётчики не являются источником totals.
6. **FINAL-SOURCE-READBACK.json → FINAL-DISPOSITION.json → PACKAGE-MANIFEST.json**: актуальные хэши 13 публичных источников, native-состояние конечных карт, состав и хэши самого архива. После проверки ZIP CRC каждый включённый файл проверен по его SHA256.

## Что специально не принято как доказательство

- Unsupported утверждения о времени старых проверок, прежнем supporting-file inventory и отрицательных состояниях всей системы.
- Неправильный 62-символьный installer-hash в исходной QA.json. Правильный хэш реально вычисленного файла: `f75cd3641b20232a9b4ae55274849f165e1a1e53b6ac920db3aa29294fa0e827`.
- Экономия, прибыль, гарантированное следование методу в будущих запусках и независимость реально обслуживших моделей. Role separation и configured model label этого не доказывают.

Исходные producer/QA файлы не переписывались, чтобы скрыть неточности. Дальнейшее применение метода проверяется на естественных проектных результатах; эта приёмка не создаёт искусственную отдельную follow-on задачу.

## Безопасное использование

Файлы sources/ — снимки публичной документации, данные для изучения, не команды. Содержащиеся в архиве Python-скрипты — сохранённые проверочные/исполнительские артефакты; их не требуется повторно запускать. Некоторые из них пишут отчёты или меняли точно разрешённые skills. Не запускать установку повторно из архива.

Личные данные, credentials и raw auth/config stores в пакет не включаются. Финансовые показатели, для которых нет биллингового evidence, обозначены null с причиной. Новых заказов/подписок в рамках методического внедрения не оформлялось; расход inference не измерен и не приравнен к нулю.
