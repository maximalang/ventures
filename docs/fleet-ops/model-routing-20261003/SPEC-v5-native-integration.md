# SPEC v5: нативная интеграция автороутинга в диспатч автокомпании

Дата: 03.10.2026. Основание: решение владельца — «автороутинг должен быть нативной
автоматической частью автокомпании; прежний роутинг со статичной выборкой модели надо
заменить на автороутинг». Опирается на: SPEC v3+v4 (роутер), CANON-MERGE (каноны 7,
8, 9, 10), релизную дисциплину fleet-policy. Исполнитель: tech. Гейт: после
независимой QA v4.

## Цель

Роутер перестаёт быть советником company и становится частью пути диспатча: при
клейме карты модель и паттерн выбираются автоматически; company теряет обязанность
ручного пина (остаётся владельцем правил). Статические дефолты профилей остаются
только как деградация для нераспознанных входов (канон 7) — замещение по классам
идёт фазой F отдельно.

## Hermes-нативность (канон «не изобретать слои», официальные примитивы)

Всё, чем пользуется автороутинг, — штатные механизмы Hermes (доки:
hermes-agent.nousresearch.com/docs/user-guide/configuring-models; integrations/providers):

| Наше понятие | Нативный примитив Hermes |
|---|---|
| Выбор модели на карту | Штатные поля kanban-карты model/provider override |
| Паттерн общения на карту | Штатный комментарий карты + скилл профиля (каноническое место поведенческих паттернов) |
| Доступность рельсы | `hermes auth` (пулы ключей, ротация) и `hermes fallback list` — источник для status-файла; файл ГЕНЕРИРУЕТСЯ script-only cron (0 токенов) из этих команд, руками не пишется |
| Точка интеграции | Существующий pre-claim guard-путь fleet-policy (официальная плагинная система Hermes); НОВЫХ демонов/слоёв нет |
| Вспомогательные вызовы | Штатные auxiliary-слоты (compression/vision/…) — роутер их НЕ трогает |
| Смена модели в сессии | Запрещена официально (предупреждение о потере кэша) — совпадает с инвариантом №5 |
| Измерение | Штатная usage-аналитика (данные state.db) — наш KPI-скрипт читает тот же источник |

Правило: если для шага нет штатного примитива — шаг не добавляется, а переиспользуется
ближайший официальный (например, алиасы `model_aliases` для имён рельс в ROUTES).

## Deliverables

1. `router_hook.py` (≤220 строк, stdlib, 0 сети) в `profiles/company/scripts/`:
   - Вход: JSON карты (title, body, task_type, protected, owner_facing,
     prior_run_failed, author_model) — те же поля, что `model_router.py --card`.
   - Режимы из `ROUTER_ACTIVE.json` (лежит рядом): {"mode": "off|shadow|enforce",
     "classes": ["ops"], "status_file": null}.
     * off — выход пустой, ничего не делает;
     * shadow — пишет строку в ROUTING-LOG.md, модель НЕ ставит;
     * enforce (только для классов из "classes") — возвращает model+provider+
       pattern; класс вне списка — как shadow.
   - Деградация (канон 7): нет поля task_type → рекомендация «default: профильный
     дефолт», строка в лог с пометкой degrade; битый ROUTER_ACTIVE.json → режим off.
   - Доступность (канон 7): status_file с {"<provider>": {"available": false}} —
     пропуск рельсы до выбора; файла нет — все доступны.
   - `--selftest` ≥6 кейсов (off/shadow/enforce/класс вне списка/нет task_type/
     статус-скип) — exit 0.
2. Интеграция в pre-claim путь диспатча: вызов hook в том же месте, где уже стоит
   пре-диспатч проверка (рядом с card_readiness.py), ONLY за флагом; ставит
   model_override при enforce и добавляет комментарий «ROUTER vN: модель+паттерн+
   rules_sha» на карту. Внедрение — интеграционным PR по релизной дисциплине
   fleet-policy (версия = trunk+1, единый activation SHA, CI на exact head);
   принудительный режим изначально НЕ включается (mode=shadow в поставке).
3. `ROUTING-LOG.md` автоматически пополняется hook'ом (формат строки уже задан);
   ручные строки company сохраняются.

## Acceptance

- `--selftest` exit 0; wc -l ≤220; сетевых импортов 0.
- В shadow: лог растёт, model_override на картах НЕ появляется (проверка на
  тестовой карте).
- В enforce на тестовой карте своего класса: model_override соответствует
  первому подходящему элементу списка ROUTES; комментарий с rules_sha на месте.
- Интеграционный PR: CI green на exact head, QA-верификация независимой моделью.
- Откат: ROUTER_ACTIVE.json → {"mode": "off"} — поведение диспатча идентично
  прежнему (это и есть rollback-гейт).

## Запрещено

- Не трогать дефолты профилей (фаза F — отдельно, owner-brief с числами по классу).
- Не менять dispatcher core/кроны/gateway; не запускать live inference; .env* не
  открывать; платных API нет (AgentRouter не используется).
- Не включать enforce на продуктивных классах в рамках этой карты — только
  shadow; канарейка классов = отдельное решение company после недели тени.
