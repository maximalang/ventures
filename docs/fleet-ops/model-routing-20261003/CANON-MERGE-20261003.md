# CANON-MERGE: сличение официальных практик с нашей схемой и объединение

Дата: 03.10.2026 (вечер). Автор: company. Основание: прямое поручение владельца —
«взять официальные каноны практики, сравнить с моей схемой, объединить, проанализировать
ещё раз и улучшить конечный автороутинг до полноценного, оптимизированного,
качественного и стабильного результата».

Источники канона: RESEARCH.md (10 паттернов, каждое число с URL) + инварианты
программы №1–5. Наша схема: SPEC v3 (ROUTES 7 классов × preference lists, first-fit,
5 жёстких правил, PATTERNS, selftest).

## 2. Объединённая архитектура (итог = v3 + 5 дельт)

Ядро неизменно: класс → упорядоченный список → первый подходящий; неудача — шаг
вправо с логом. Дельты упрочнения (детали: SPEC-router-v4-hardening.md):

1. **Ввод доступности** (канон 7): опциональный --status, пропуск мёртвой рельсы ДО
   старта; нет файла — все живы. Ничего не падает.
2. **Аудит-мета** (канон 9): в выводе — версия роутера и отпечаток правил (sha);
   два прогона на одном входе — одинаковый отпечаток. Воспроизводимость для evals.
3. **KPI-тройка** (каноны 4+9): QA-block rate по классам, override share, escalation
   rate — из shadow-лога и вердиктов qa, сверка с BASELINE еженедельно.
4. **Канарейка по классам** (канон 10): ops → code → research → review; strategic и
   vision — только вручную; откат класса — правка одной строки.
5. **Лестница вверх** (канон 3): повышение рунга (веса/семантика) — только при
   измеренном дефиците простых правил, не по моде.

## 3. Повторный анализ объединённой схемы (второй проход)

- **Простота:** рунг 1 сохранён; новых зависимостей 0; код остаётся stdlib-словарём
  (лимит 280 строк); решение по-прежнему 0 токенов и <1 мс.
- **Стабильность:** деградация безопасна в обе стороны (нет --status → все доступны;
  нет маркеров класса → устойчивый маппинг task_type→класс); детерминизм подтверждается
  отпечатком правил; откат любой доли — правка строки списка или отказ от пина.
- **Качество:** независимая qa на чужой модели после каждой версии; KPI-тройка ловит
  регрессию по классам до того, как она станет нормой; канарейка не даёт «включить всё
  сразу» (аналог инцидента −9 п. accuracy из досье).
- **Стоимость:** кэш-дисциплина (та же модель на повторной работе) держит скидку
  кэша; пропуск мёртвой рельсы не сжигает диспатчи в 429; дорогая квота не тратится
  на рутину (бинарное дёшево/дорого внутри класса).
- **Остаточные риски:** (а) ошибочная маркировка класса компанией — ловится override
  share и shadow-логом; (б) устаревший --status — лечится деградацией по умолчанию;
  (в) дрейф качества модели — ловится QA-block rate по классам. Все три риска имеют
  владельца (company) и метрику.
