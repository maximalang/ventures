# SYNTHESIS-PROTOCOL — протокол синтеза owner-задач (v1, карта t_234de1e7)

Статус: канон программы model-routing (program-docs: этот каталог —
docs/fleet-ops/model-routing-20261003/, PROGRAM.md и SPEC-*). Директива
владельца 04.10: «не просто зафиксировать в правило, а правильно интегрировать
в общение». Канон авторства карт: kanban-card-authoring skill (пропатчен
company 04.10) — этот протокол расширяет его на все меж-агентные поверхности.

Правило 0. **Слова владельца — INPUT, никогда не dispatched-текст.** Дословная
трансляция owner-формулировок в карты/брифы/delegation-контекст — авторский
дефект.

## Конвейер (6 шагов)

1. **Intake.** Зафиксировать сырую директиву дословно (цитата + дата + канал).
   Определить: цель, затронутые поверхности, blast radius, что НЕ запрошено.
2. **Декомпозиция.** Разложить на: deliverables, пробелы (gaps), двусмысленности
   (ambiguities), скрытые зависимости, evidence-шаги, гейты, метрики, rollback.
3. **Синтез в более широкую профессиональную форму.** Добавить подразумеваемые
   директивой шаги (evidence, gates, measurement, rollback, смежные поверхности),
   НЕ сужая до конкретной детали, которую владелец случайно упомянул.
   Профессиональная форма = язык домена (термины vendor-документации и канона
   программы), а не бытовая формулировка владельца.
4. **Вопросы одной формой при пробелах.** Материальные пробелы → ОДИН пакет
   вопросов владельцу до диспатча (одна форма/одно сообщение, не серия
   уточнений по ходу). Нематериальные → задокументированное допущение в карте.
5. **Диспатч с паттерном модели.** Каждая карта/делегация несёт официальный
   паттерн целевой модели (PATTERNS v2): `python scripts/model_router.py
   --patterns <model>` → блок из 6 строк (как брифовать / требовать строго /
   страховка / анти-паттерн / канонические настройки / источники) вставляется
   в спецификацию исполнителю. Автоповерхности: штамп hook на claim
   (router_bridge.apply_override, блок «PATTERN v2 (<model>):»), шаблоны
   templates/BRAIN-BRIEF.md, templates/HANDS-DELIVERABLE.md,
   templates/DELEGATION-CONTEXT.md. Паттерны — только vendor-цитаты
   (PATTERNS-SOURCES-v2.md); без цитаты не добавляются (правило «брать
   в интернете и не выдумывать»).
6. **Отчёт человеческим языком.** Итог владельцу — не дампом артефактов,
   а связным ответом на исходный вопрос: что сделано, что проверено
   (evidence: команды/exit-коды/SHA/URL), риски, что требует решения.
   Формат отчёта владельца: контекст → решение → риски → проверки/evidence →
   изменённые файлы → suggested commit message.

## Границы

- Протокол не отменяет kanban-lifecycle: task_type обязателен, owner-guard,
  gate-арминг и approval-границы — по fleet-policy.
- Синтез ≠ расширение мандата: новые spend/deploy/юридические поверхности —
  только через APPROVALS.md.
- Протокол применяется ко ВСЕМ меж-агентным поверхностям: тела карт, brain-brief,
  hands-deliverable, контексты субагентов (delegate_task), комментарии-handoff.
