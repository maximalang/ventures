## Дельты (ровно пять)

D1. **--status <file.json>** (канон 7): опциональный ввод
    {"<provider>": {"available": false}} и/или {"<model>": {"available": false}};
    недоступные записи пропускаются ДО выбора (это маршрутизация, не failover);
    файла нет / битый / пустой → все считаются доступными, предупреждение в
    rules_fired. Пример: {"openai-codex": {"available": false}}.
D2. **Аудит-мета** (канон 9): вывод JSON дополнен
    "router_version": "v4", "rules_sha": sha1(канонический дамп ROUTES+PATTERNS)[:12],
    "input_echo": {использованные поля входа}. Два прогона на одном входе —
    идентичный rules_sha (детерминизм). --print-rules печатает rules_sha первой строкой.
D3. **Selftest +3 кейса**: (a) --status с недоступным провайдером меняет выбор на
    следующий элемент списка; (b) вход без единого маркера → устойчивый маппинг
    task_type→класс, не ошибка; (c) protected в title → strategic. Итого в selftest
    ≥9 кейсов.
D4. **ROUTING.md** (лимит поднят до ≤140 строк): добавить разделы — KPI-тройка
    (QA-block rate по классам / override share / escalation rate, источник —
    ROUTING-LOG.md и вердикты qa, сверка с BASELINE-20261003.json еженедельно);
    порядок канарейки ops → code → research → review (strategic и vision — только
    вручную); «лестница вверх» — рунг 2 допустим только при override share >30% на
    классе две недели подряд; порядок величины overhead (<1 мс, канон) и кэш-обоснование
    правила повтора (та же модель на повторной работе; кэш-хиты ~10% цены input).
D5. **Cache-discipline правило** (канон 8): в PATTERNS/правилах явно: повторная карта
    той же работы рекомендует ту же модель; единственная причина смены —
    prior_run_failed (шаг вправо с логом). Число-обоснование (кэш-скидка до 90%,
    Anthropic) — в ROUTING.md.
