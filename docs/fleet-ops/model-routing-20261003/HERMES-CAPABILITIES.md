# HERMES-CAPABILITIES: стабильные возможности Hermes, выжатые под автороутинг

Дата: 03.10.2026. Основание: поручение владельца — «изучить ещё лучшие стабильные
возможности Hermes и использовать их на максимум для автороутинга». Источник — только
официальные доки Hermes (URL у каждого пункта).

## Принято к использованию (сейчас)

1. **Нативные фолбэк-цепочки** — `fallback_providers:` в config.yaml + команды
   `hermes fallback add|list|remove|clear`; три официальных слоя устойчивости:
   пулы ключей (ротация same-provider) → primary model fallback (cross-provider,
   с сохранением разговора) → auxiliary task fallback (независимый резолв слотов).
   Анти-флап из коробки: провайдер с названным reset-временем садится на скамейку
   ДО этого момента; без названия — экспонента 60с→4ч; `fallback.min_switch_reset_seconds`
   (напр. 120) не даёт.switchиться, если primary вот-вот откроется.
   Решение: ЖИВЫЕ цепочки для интерактивных профилей (company/default по доктрине
   Sol→GLM-flash→Qwen — сегодня они есть только на бумаге; qa уже имеет один шаг);
   воркерским профилям кросс-модельные цепочки НЕ ставим (канон независимости:
   смена модели mid-run отравляет аттестацию авторства; доступность для воркеров
   решает роутер ДО диспатча). Карта: rails-v22-native-fallbacks.
   URL: /docs/user-guide/features/fallback-providers
2. **Диспетчеризация как контракт воркер-лейнов** — диспатчер матчит assignee на
   профиль-лейн и спавнит `hermes -p <profile> chat -q` с полным набором
   HERMES_KANBAN_* env; неразрешимый assignee даёт событие skipped_nonspawnable, а
   не тихое падение; плагинные non-spawnable лейны — официальная точка расширения.
   Решение: наш router_hook живёт ровно в этом контракте (pre-claim guard
   fleet-policy, официальный плагинный механизм). URL: /docs/user-guide/features/kanban-worker-lanes
3. **Script-only cron (без LLM)** — сценарий по расписанию, stdout уходит в
   доставку, ноль токенов. Решение: генератор status-файла доступности рельс для
   роутера (из `hermes fallback list` + состояния пулов) и еженедельный KPI-прогон —
   оба как script-only cron. URL: /docs/guides/cron-script-only
4. **Рантайм-резолвер провайдеров** — единый резолв для CLI/gateway/cron/auxiliary;
   приоритет: явный запрос → config.yaml → env → дефолты; провайдер-плагины
   декларируют api_mode/base_url/env_vars/fallback_models; пользовательские плагины
   перекрывают bundled. Решение: ROUTES ссылается только на реально
   зарегистрированные провайдеры; смена рельсы = правка конфига, а не кода.
   URL: /docs/developer-guide/provider-runtime
5. **Auxiliary-слоты с независимым резолвом** — compression/vision/skills/approval/
   summarization уже развязаны по слотам (у флота так и настроено: зрение Luna,
   остальное Qwen max). Роутер их не трогает — совпадает с официальным дизайном.
   URL: /docs/user-guide/configuring-models

## Принято позже (по триггеру)

6. **model_aliases** (short/full, свои ключи на алиас) — когда списки ROUTES
   устоятся после тени: короткие имена рельс во всех профилях вместо длинных строк.
   Триггер: конец канарейки классов. URL: providers-and-models (reference скилла hermes-agent)
7. **Пулы ключей с ротацией** (`hermes auth`) — расширение пула zai/openai-codex
   сверх существующих ключей требует новых креденшелов = владелец; структура пулов
   уже используется. Триггер: голод квоты на канарейке. URL: /docs/user-guide/features/fallback-providers (§credential pools)
8. **Subscription Proxy** (Nous Portal как OpenAI-совместимая точка) — новая рельса;
   запрещено без необходимости (канон «не расширять пул»). Триггер: owner-brief.

## Не применимо к автороутингу

- Context Engine Plugins — про контекст, не про выбор модели.
- Bot Mode — рельсы поверх профилей; вне текущей фазы.
- Import from Other Agents, Honcho — не про роутинг.

## Слияние с инвариантами флота

Единственное доктринальное расхождение: официальный primary fallback умеет менять
модель mid-session (сохраняя разговор). Флот-канон строже для ИСПОЛНИТЕЛЕЙ
(независимость авторства): воркеры — пауза/эскалация, доступность решается до
старта. Для ИНТЕРАКТИВНЫХ поверхностей (чат с владельцем) нативный фолбэк —
именно то, что нужно: разговор не рвётся. Разведение зафиксировано в ROUTING.md.
