# Программа «Рельсы v2.2» — простой автороутинг + паттерны общения

Дата: 03.10.2026 (v2.2 — вторая коррекция владельца). Владелец результата: company.

## Коррекции владельца (03.10)

1. «Надо поставить правильный и хороший автороутинг — это и мозг, и агентов разгрузит;
   для каждой модели — свои правильные паттерны общения.»
2. «Должно быть более логично и профессионально, а самое главное — просто и оптимизировано.»

Вывод: архитектура v2.1 (паспорта с capability-векторами, числовой скоринг,
status-файлы квот) избыточна для масштаба флота. Действительна эта версия.

## Логика (одна строка)

Задача → класс → упорядоченный список моделей → первый подходящий.
Неудача/блок → шаг вправо по списку (явный пер-картовый пин, с логом и причиной).

Это производственный стандарт (ordered preference lists): объяснимо, детерминировано,
0 токенов на решение, < 1 мс. Никаких скорингов и весов — порядок в списке и есть
решение, и он обоснован числами канона.

## Что входит в систему (минимум артефактов)

1. **model_router.py** (≈150–250 строк, stdlib, 0 сети): внутри — единый источник
   правды ROUTES: 7 классов (code, data, research, ops, review, strategic, vision) с
   упорядоченными списками по 2 модели; жёсткие правила (review исключает модель
   автора; strategic/owner-facing → топ-рельса; needs_vision → vision-класс;
   prior_run_failed → сразу следующий элемент); PATTERNS — на каждую модель короткий
   блок «как брифить / что потребовать / страховка / анти-паттерн», выдаётся вместе с
   рекомендацией для вставки в спецификацию. CLI: --card, --selftest, --print-rules.
2. **ROUTING.md** (≤120 строк): человекочитаемая политика — те же списки с
   обоснованием «число+источник», правила, эскалация, инварианты, сжатая таблица
   паттернов. Согласована с --print-rules.
3. **ROUTING-LOG.md** (фаза C): по одной строке на диспатч — рекомендация vs факт,
   применённый паттерн. Всё.

## Инварианты (5, коротко)

1. Выбор модели — только ДО старта задачи; тихой подмены на ходу нет.
2. Проверяющий всегда на чужой модели (review исключает author_model).
3. DashScope-модели — reasoning max (конфиг-уровень); qwen-vl-max — без effort.
4. TG = qwen3.8-max и дефолты профилей — только словом владельца.
5. Внутри живой сессии модель не переключаем (prompt cache).

## Метрики, kill, rollback

- Стоимость: delta от BASELINE-20261003.json (токены по рельсам; included≠бесплатно).
- Качество: QA-block rate по классам; доля Override'ов company поверх рекомендаций (цель — к нулю: мера разгрузки).
- Kill: QA-block rate вырос на классе → класс на канон-порядок; голод квоты → доклад владельцу.
- Rollback: перестать применять пины (все в ROUTING-LOG.md); списки правятся одной строкой.
