## Levers (typical impact order)

1. **Session hygiene** — biggest free lever. Long-lived sessions re-transmit context every turn; a 17–20k-message session is a per-turn tax. `/new` after big tasks; `hermes sessions archive/delete/prune` for dead ones. PITFALL: legacy `session_reset.*` config keys (mode/idle_minutes/at_hour) are ignored by the bare kernel (UPDATE 2026-10-03 per evidence-root DECISION-AND-CONTRACT.md: plugin hermes-session-reset-policy 0.3.0 IS installed on this host and implements session_reset — the old blanket «reset keys are inert» advice is incomplete here; owner directive 2026-10-03: do NOT shorten/reset/archive sessions as an economy shortcut — this correction is not a permission to reset/restart) — gateway sessions end only on explicit `/new`/`/reset`, compression stays automatic. Never promise timer-based auto-reset because a config block exists: verify a config key is actually read by the installed kernel (grep it in config_defaults.py / runtime / installed plugins) before advising the owner. Background fleet work is unaffected either way — every cron fire and kanban dispatch starts a fresh session; `/new` hygiene matters only for interactive chats.
2. **MoA fan-out** — with MoA enabled each user turn pays reference models + aggregator. Real switch is preset-level: `hermes config set moa.presets.default.enabled false` (see pitfalls).
3. **Compression** — `hermes config set compression.protect_last_n / target_ratio / protect_first_n`.
4. **Reasoning effort — ЗАПРЕЩЁННЫЙ рычаг на DashScope-профилях.** Директива владельца (20.09, подтверждена жёстко 22.09): все DashScope-модели (qwen3.8-max, kimi-k3) во всех слотах (main, delegation, ВСЕ auxiliary) = reasoning **max**, «можно не экономить». Никаких max→high/low даунгрейдов на DashScope, включая тривиальные aux (title_generation, memory_query_rewrite и т.п.) — даже когда замеры показывают перерасход. Перед любым предложением по effort — сверить fleet-doctrine «Aux offloads paid rails». Effort-правки допустимы только на GPT-профилях и только с явного одобрения владельца.
5. **Skills index** — disable never-loaded skills via `skills.disabled` in config.yaml (reversible, files untouched). Stronger variant when hundreds of zero-use skills sit on disk: physical quarantine (reversible mv + `.no-bundled-skills` marker so updates don't re-seed bundled copies) — full procedure and pitfalls in skill `fleet-skills-rollout` §«Карантин zero-use скиллов по флоту». Estimate ≈ name + min(desc,140) chars per skill per fresh prompt. Measured (02.09): 64 disables → skills index 16,421→11,078 chars (−33%, ≈1.3k tokens per fresh prompt); verify with `hermes prompt-size --json` before/after. Note: skills disabled in ONE profile's config only shrink that profile's prompts; each profile loads its own skills tree.
6. **Cron delivery targets** — `bot-chat:<profile>` resumes that profile's Bot Chat session and runs a FULL agent turn every fire; drop it when the real channel is Telegram, and keep bot-chat sessions short.
