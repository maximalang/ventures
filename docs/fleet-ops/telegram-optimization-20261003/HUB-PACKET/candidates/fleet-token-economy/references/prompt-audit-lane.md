## Prompt-audit лейн (канон 25.09, адаптация Anthropic /claude-api prompt-audit)

Подход Anthropic: аудит промптов/скиллов/памяти против ТЕКУЩЕЙ модели. Два вида устаревшего текста: (1) «буквальные» инструкции («проверь дважды», «будь максимально тщателен», самодельный scratchpad, жёсткие N-шаговые скрипты) — жгут токены (до −⅓ стоимости задачи при удалении); (2) текст под мёртвые модели/профили/противоречивые правила — жжёт точность (−7…11 пп). Замеры Anthropic: устаревший промпт = +36% стоимости; после аудита −14% стоимости и точность 92→97%. Команду `/claude-api prompt-audit` НЕ переносить — это Claude-Code-специфика; у нас свой детектор.

Наша реализация: `profiles/company/scripts/prompt_audit.py` — no-agent cron `d341b0d4a136` daily-prompt-audit (ЕЖЕДНЕВНО 08:15; до 30.09 был еженедельным), доставляет в тред 281, молчит при неизменённом hash находок (`prompt_audit.state.json` — watermark как у deny_triage/cap_tool_watch). Рубрики находок (объективные, малошумные): P1 мёртвая маршрутизация (@rr-*, rr-critic/ops/pool/mkt-lead/mkt-smm/support/frontend/backend), P2 мёртвые пины моделей (ox-alpha/stealth/ox, gpt-5.6-luna, gpt-account-2/terra), P3 «проверь дважды»-антипаттерны (verify twice / double-check your work / scratchpad / step by step), P5 MEMORY>7400 / USER>2350 / SOUL>9000 (warning-полоса перед жёсткими потолками 8000/2500). INFO-строка вне hash: число desc>60. Исключения (false-positive guard): строки-надгробия («удалены/removed» — историческая справка о миграции, НЕ маршрутизация), author/created_by/owner-поля frontmatter скиллов, rr-team (живая доска), rr-project/rr-landing (живые скиллы), rr-* worktree-папки и repo-индексы. Новые живые сущности с rr-префиксом → править DEAD_PROFILE/TOMBSTONE, не отключать рубрику.

Разделение труда (каноны 30.09): скрипт = детектор (read-only, 0 токенов); потребитель находок — cron `9bf1839bf40f` weekly-audit-remediation (пт 08:25, сразу после token-audit 08:00 и prompt-audit 08:15; читает cron/output/d341b0d4a136/ + prompt_audit.state.json + job metadata, контракт reports/audit-action-contract-20260930.md): P5 — отдельно с сохранением канона владельца, P1/P2 — по root cause (P4 не существует с 30.09 — INFO-строка), всё через native kanban fleet-ops с независимым QA.
