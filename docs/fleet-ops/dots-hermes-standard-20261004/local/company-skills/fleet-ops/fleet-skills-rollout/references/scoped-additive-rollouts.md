# Scoped additive reference rollouts

Use for one accepted reference plus a small load-hook across existing, possibly different skill revisions. This procedure is not authority to edit other profiles; require an explicit target allowlist and existing Fleet Policy permissions.

- Freeze the exact reference, hook, target root paths and before hashes. Enumerate count and case-insensitive collisions programmatically. Preserve each root revision; byte-identical added references do not require whole-root equality.
- Back up raw target bytes and reference existence before writes. Recheck current hashes immediately before each atomic write; drift/collision means leave that target unchanged and report a scoped gap. Do not follow relocated paths or resurrect removed copies.
- Verify reference byte equality, exactly one hook, root minus own hook equal to own backup, frontmatter and supported loader registration for each target. Natural skill_view proves accessibility in that run, not future compliance. Inventory-only checks do not prove historical supporting-file preservation without a captured before manifest.
- Keep documentation/source accuracy, installation, natural load, semantic scenario review, live behavior and economic benefit as separate acceptance layers. A completed run, configured model label, or prose PASS does not attest those other layers.
- Parse real check dictionaries and manifests for totals/hashes. Reject malformed fingerprint literals before lookup; keep the literal and record the actual independently computed hash separately. Never copy reported test totals into final acceptance without recounting actual receipts. Match canonical task state and successful run outcome separately; a synthesized manual-completion run can carry a different status token than a worker completion. Preserve the actual values rather than requiring or rewriting one status spelling.
- Preserve original frozen reports when adding errata. A factual correction must identify the original hash/locus, precise replacement, proof and acceptance effect. Independent QA may exclude unsupported documentation claims when actual subject facts still pass; it cannot waive missing/failed functional, integrity, access or behavior evidence.
- Avoid correction-card cascades for harmless report transcription errors: the active authorized reviewer corrects its own report; the consumer uses exact verified receipts and declares bounded exclusions. Escalate or re-scope the existing lane only if a required subject/acceptance criterion truly fails.
- Roll back only own hook/reference. Check freshness of BOTH current root and reference against operation after hashes before restoring/deleting. Stop on later edits; do not delete a changed reference or blind-restore an old whole-root backup.
- Keep served-model lineage unknown unless evidenced by permitted natural-run metadata. Reviewer role separation is not proof of model-family independence. Do not generate paid synthetic inference solely for rollout attestation.
- Report financial scope, period and source. No new subscription/order is not zero inference cost; unmeasured revenue/refunds/costs/usage remain null. Never claim savings from installation-only checks.
