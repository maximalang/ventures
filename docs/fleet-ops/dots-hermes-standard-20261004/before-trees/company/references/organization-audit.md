# Auditing AI-organization quality

## Safety precedence and evidence corrections

Historical recovery anecdotes below are NOT authorizations. Never change tool, command spelling, task identity, path construction, or caller identity to evade a denied action. A pristine clone or a comment claiming approval is not an exact authorization. Preserve stopped runs and resolve the cause through supported authorized recovery.

Unchanged source SHA and green CI do not preserve a release verdict when later findings remain unresolved. Read the latest material review and every live prerequisite; never restart an older parallel release card that lacks the newer safety dependencies.

Treat author test results, independent probe execution, and independent signed verdict as separate evidence. A probe that crashes while emitting its receipt is incomplete; fixed source without a successful authorized rerun is not a pass. Path-string containment and selected unchanged sentinel files alone do not prove that no live file was opened. A push to a filesystem origin is local delivery, not GitHub publication.

Audit goal-to-outcome flow rather than adding roles or counting completed cards. Preserve existing risk gates; distinguish safety, liveness, product usefulness, or measurement defects before proposing fixes.

- Do not infer that a checkpoint lacks a machine carrier because a native list DTO has no check_at column. Inspect latest_summary.metadata, native one-shot cron and scheduled-task consumers before adding schema or a wake engine; test a due WAIT's actual continuation, not field presence.
- Reject a green replay/schema draft as activation evidence when its live adapter prints a note or always raises not-activated. Exercise a genuine native read, refuse a task-bound context before IO, remove hardcoded census/HEAD/wake claims, and verify exact native targets outside the author-supplied receipt.
- Treat quota reset as acknowledgement of a bounded batch, not a one-attempt bypass. Test reset followed by multiple new quota terminals; a new failure must not resurrect old acknowledged history, and automatic/tied/malformed events must not grant reset authority.
- For independent CLI reviews, use a fresh unique native named session (`chat -c <unique> --create-if-missing`) so user-provenance title suppresses automatic title inference without altering config. Read the FULL final usage ledger, including auxiliary rows; a terminal error's zero-token result is not a session/cost ledger, and any author-model intersection prevents an independent PASS.
- Do not accept author-echoed timestamps/job IDs as WAIT evidence. The outcome consumer must read the exact native job/profile, one-shot/repeat state, actual next_run_at and content-bound observation target; a no-agent timer proves scheduling only, not company continuation. Enforce real timestamp freshness rather than trusting a fresh boolean.
- Test native one-shot scheduling with an explicitly scoped no-agent canary, local delivery, repeat=1 and a script filename under the active profile scripts directory. Read exact native terminal state AND the actual output marker; script execution alone does not prove company wake, hosted loaded-code identity or owner delivery.
- Treat a cron [SILENT] as an output-suppression token, not proof of no action. Read the exact own-journal key/time window and native action receipt; legacy push exit 0 is not a durable ACK or owner-delivery receipt.
- Do not turn unsupported private-repo rule supplements or routine QA quota into owner payment requests. Preserve fail-closed acceptance, use an eligible independent route and existing evidence, and escalate only the genuine new paid/ownership/risk boundary.

- Diagnose both failure directions: rejecting harmless reads is a liveness defect, while role-wide gate exemptions and historical PASS acceptance are safety defects. Never propose globally weakening gates as a cure for false denies.
- Treat native recovery coverage as an acceptance criterion: check create/link and their authorized repair counterparts (revise/promote/unlink/archive), preservation of task identity, and positive evidence dependencies. Missing recovery plus replacement-card proliferation is control-plane debt, not worker underperformance.
- Separate scope-limited QA from whole-artifact readiness: a green regression suite or successful marker delivery does not refute a later adversarial finding on the same head. Preserve that distinction in owner reports.
- A localhost HTTP 200 is not a health proof: inspect response type and body, rule out proxy/SPA fallback, and distinguish the gateway's recorded startup state from fresh process/functional evidence. Do not call a gateway down from one refused unverified port.
- Interpret empty ready/running queues as a point-in-time observation, not proof of chronic starvation. Trace explicit holds, parked products, and broken dependencies before attributing causes or estimating productivity.

- Known defect classes to probe: review-role gate waivers, stale PASS after later FAIL, missing native recovery tools (unlink/archive), self-declared spend, decision metrics that count volume not accuracy, budget guards that default unknown spend to zero.
- Provenance rule: every finding carries file:line + full SHA; distinguish proven bug from design risk. Auditor credibility follows evidence, not role; company re-verifies reviewer claims against source before acting (several reviewer claims were overstated in the 05.09 audit).
- Runtime probe pattern (05.09): registry tests only on temporary boards, no live board mutations; offline classifier probes through temp venv on SHA-pinned source copy in %LOCALAPPDATA%/Temp; live gateway checks read-only (curl /health, PID via PowerShell process listing); PR state via gh api GET on exact head.
- Repair chain shape: one tech implementation card (RED/GREEN per fix, minimal restrictive diff, preserve existing PR diff, non-force updates) → one independent QA card on the exact repaired head (repro evidence on the old head is not a verdict) → ops activation card with timestamped backup. Rollout held until QA PASS on the new head.
- False-stop handling (c2001/c2102 class): long read-only shell inspection chains collapse into one deny signature and trip same_failure_loop. Steering contract: read_file(offset,limit) + search_files(file_glob=...) instead of shell chains; keep keyword-bearing test payloads inside workspace files, run via short 'python check.py'; first new deny = stop with evidence.
- Fourth false-deny class (05.09, t_801babcf): policy-repair work itself trips the policy's lexical rules — worker_self_approval fires when command/source text contains approve/revoke/approvals words. Working recovery: verify clone pristine, post unblock decision, then 5 instrument rules: read_file/search_files only (zero shell inspection chains), keyword payloads inside workspace files run via short `python x.py`, short git commands with SHA references (never trunk name in command string), progress.md to workspace on FIRST deny of any kind then orderly finish, ~30-call budget per run with clean handoff. Pre-create replacement QA as child of the repair parent so the release chain never depends on a triage-locked QA card (t_f9a2254a pattern).
- A card in triage after 3+ distinct false denies has no runtime specify/promote (verified missing from the tool catalog 05.09): recovery = light replacement card bound to the exact new head; preserve the old card's workspace/artifacts as repro evidence — the denies themselves document the lexical-boundary finding.
- Lifecycle-gating false-deny (5th confirmed case, 05.09, t_3a9fa261): worker finishes real work, then kanban_complete is denied by same_failure_loop (collapsed deny-counter from earlier policy hits in the same run). Established tactic: worker records result + evidence in workspace/attachment file (canonical artifact), company verifies byte-level hash and closes the card from its own name citing the artifact. Candidate requirement for the policy repair backlog (item E, lifecycle-immunity): deny suppression must cover complete/heartbeat/comment/block for non-violating runs.
- Design-spec review gate (used 05.09 for DQS spec v1): dispatch a light read-only subagent review before any implementation card; require verdict APPROVE or REVISE with concrete file/section edits. REVISE findings on v1 (kill-check at baseline=0 auto-passes idle; direction-only forecast farms confidence on naturally growing metrics; green_delta defined as share ≥0 makes divergence signal degenerate; fleet-wide DQS misprices weak projects) were relayed as a v2 child card (t_3a9fa261) with parents=[v1 done] so the queue promotes it automatically. Implementation never starts from a REVISE'd v1. Company line-review of v2 (comment 2136) is orchestrator verification, not a substitute for the independent review.
- Delegate leaf audits ≤15 lines with explicit scope (files, no .env/config/DB/CLI, no gates); verify reviewer claims against source before accepting; subagent transcripts live under profiles/company/cache/delegation/live/<deleg_id>/task-N.log.
