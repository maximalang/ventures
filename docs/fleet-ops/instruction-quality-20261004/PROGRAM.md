# PROGRAM: качество инструкций — убрать повседневные правки владельца

Дата: 03.10.2026. Поручение владельца: «в каждом чате на любой модели приходится
вносить коррективы — модель делает некачественно или идёт не в ту сторону; это
недоработка инструкции; улучшить и оптимизировать отдельным этапом».

## Гипотеза

Коррективы нужны не из-за слабых моделей, а из-за устройства инструкций: (1) они
перегружены и не имеют явного приоритета — разные модели взвешивают правила
по-разному и дрейфуют; (2) у задач нет принятого загодя определения готовности —
намерение владельца извлекается правками постфактум; (3) поведенческие паттерны не
разведены по моделям (закрывается параллельной программой автороутинга).

## Этапы

- **A — аудит корректив (research, готово к запуску):** собрать из истории сессий
  повторяющиеся типы правок владельца (не в ту сторону / некачественно / лишний
  scope / игнор правил) + инвентарь инструкционных поверхностей с объёмами (SOUL,
  профильные.yaml, скиллы, memory 98%!, шаблоны карт). Deliverable:
  INSTRUCTION-DEBT.md: тип правки → частота → корневая причина → виноватая
  поверхность → предлагаемое лечение. Числа обязательны (сколько правок какого
  типа за сентябрь–октябрь по журналам сессий).
- **B — переработка (product, после A):** новый каркас: короткий ядро-слой с
  явным порядком приоритетов (безопасность > намерение владельца > evidence >
  стиль), слой флота вынесен из ядра, поверхности сокращены до необходимого.
  Deliverable: draft-каркас в этой директории; ПРИМЕНЕНИЕ — только после слова
  владельца (SOUL/профили — его канон).
- **C — пилот и замер:** применить к одному воркерскому профилю; метрика —
  correction-rate (правки владельца на задачу) до/после за 2 недели; источники:
  журнал сессий + ROUTING-LOG (override share как прокси). Развёртывание по
  профилям после чистого пилота.

## Правила

- Ничего не применять к SOUL/профилям без слова владельца.
- Memory перегружен (98%) — кандидат на консолидацию в этапе B.
- Дублирование правил между поверхностями считать дефектом каркаса.

## Финансы

0 ₽ incremental на этапы A–B (квоты research/product); этап C — по квоте профиля.
