# SPEC — Stream-Scouting (автопоиск моделей для стрим-агентств)

Статус: **PARKED** — кандидат продукта, активация по команде владельца (22.09.2026: «запомнить и потом реализовать»).
Источник идеи: оффер анонима @amb174 (04.09.2026, «скаутинг моделей на нон-нюд стримы», без условий, диалог мёртв). Решение компании: не работать на AMB; строить самостоятельно как B2B lead-gen.
Карточки: portfolio hypothesis card (ссылка в теле карты), бэклог venture-lab т_7b691dcd (комментарии 92–94).

## 1. Продукт
Двусторонний lead-gen: находим стрим-агентства, которым нужны модели (нон-нюд: Kick/Twitch just-chatting и т.п.), автоматически находим и скорим кандидатов-моделей на публичных платформах, доставляем оффер и передаём агентствам за bounty / rev-share (рынок скаут-процента 10–20% с прибыли моделей; у активных скаутов 50–90 т₽/мес — agency-caramel.com).

Метрика (при активации): `signed_streaming_models_28d` или `paid_bounties_28d` — уточнить после первых договоров (платят за модель, вышедшую в эфир, не за лид).

## 2. Порядок работ (железный)
1. **Агентства 먼저**: карта 10–20 агентств → извлечение условий (%, bounty, договор, площадки) → 2–3 подписанные договорённости. Без этого — никакого outreach. Контакт с агентствами делает человек/входящие, не бот.
2. **Discovery-пайплайн** (можно строить параллельно, база накапливается заранее).
3. **Warmup пула outreach-аккаунтов** (≥30 дней на аккаунт).
4. **Тест outreach** малым объёмом (1 аккаунт, десятки/день, consent-фрейминг «предложение работы»).
5. **Масштаб** только при положительной unit-экономике: стоимость контакта → ответ → подписанный контракт → первый эфир → выплата.

## 4. Outreach-правила (hard)
- Fleet TG-аккаунт (@botassistanthub, +79009666092) **не участвует никогда** — инфраструктура уведомлений владельца.
- Пул 2–3 отдельных TG/VK-аккаунтов: каждый = свой номер (**paid capability, нужен владелец**; виртуальные SMS часто банятся TG навсегда по номеру), свой api_id, резидентный/мобильный прокси ~300–1500 ₽/мес/акк (Donut: профили+прокси+fingerprint), warmup ≥30 дней.
- Массовый unsolicited outreach = serious escalation → явный GO владельца после справки о рисках (данная справка зафиксирована в т_7b691dcd комм.93).
- Ротация шаблонов + персонализация; обработка FLOOD_WAIT/PEER_FLOOD = стоп, не обход.

## 5. Юридические риски (evidence 22.09.2026)
- Холодная рекламная рассылка без согласия: ст.18 ФЗ «О рекламе», КоАП 14.3 ч.4.1 — граждане 10–20 т₽, юрлица 300 т₽–1 млн ₽ за рассылку; ФАС 05.03.2026 ужесточила позицию по TG. Митигция: оффер работы (не реклама товара), inbound-каналы с явным согласием.
- 152-ФЗ: парсинг/хранение ПДн кандидатов — минимум полей, ограниченный срок, фиксация согласия при первом контакте, удаление по требованию.
- Ниша серая: только строгий non-adult; дрейф агентства в 18+ = немедленный стоп (уголовные риски). Проверка площадок/офферов агентства до подписания.
- TG-антиспам: бан по номеру навсегда; аккаунты <30 дней под жёсткими лимитами; USER_PRIVACY_RESTRICT у большинства получателей.

## 6. Стек
Donut (аккаунт-пул, прокси, fingerprint), scrapling (stealth-парсинг), streamscharts/публичные страницы Kick/Twitch, telethon (отдельные сессии), tiktok/instagram/youtube скиллы, CRM-атрибуция lead→контракт→эфир→bounty (критично: иначе агентства объявят модели self-lead и не заплатят).

## 7. Экономика и kill criteria
Пилот ~0 ₽ cash (кроме прокси/номеров при активации outreach), 2–3 дня research + discovery. Потолок при работающем потоке: десятки–сотни т₽/мес (объёмная автоматизация без пропорциональных рук).
Kill: нет подписанных условий с ≥1 агентством за 2 недели активной фазы; первая неоплата bounty после подтверждённого эфира; требование масс-аутрича с флотовых аккаунтов; требование участия в adult-контенте.

## 8. Границы владельца (preconditions активации)
1. GO владельца на массовый outreach (serious escalation).
2. Выдача/оплата отдельного номера(ов) для outreach-аккаунтов (телефон = только с подтверждения владельца — правило 22.09).
3. Бюджет на прокси (~1–3 т₽/мес).
4. Юробвязка для приёма bounty (самозанятый есть; сверить с финотделом до первого платежа).
