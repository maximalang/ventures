## Задача
Спроектировать **совмещённые монетизационные стеки**: как один произведённый ролик/ниша приносит деньги из нескольких источников одновременно, не нарушая правила площадок и не плодя лишнюю работу.

## Ключевые принципы, которые проверить (не принимать на веру — подтвердить или опровергнуть evidence'ом)
1. **Один ролик → много площадок (repurposing)**: вертикальный клип публикуется на YT Shorts, VK Клипы, TikTok, IG Reels, Дзен, Pinterest. Какие механизмы монетизации не конфликтуют при кросс-постинге? Где эксклюзивность убивает выплату (например, клиппинг-кампании с требованием «только эта площадка», VK-требование оригинальности, Klipni-проверка дублей)?
2. **Один ролик → несколько слоёв дохода на одной площадке**: платформа-выплата + партнёрская ссылка в описании + донат + свой продукт. Что из этого реально совмещается (например, VK: rev share + ссылка в описании + VK Donut; YouTube: клиппинг-кампания Klipni + affiliate в описании + спонсорство)?
3. **Конфликты и антагонизмы**: какие механизмы взаимоисключающи (ERID-маркировка рекламы vs партнёрские ссылки? клиппинг-кампания запрещает сторонние ссылки? стоки требуют эксклюзив? музыкальные промо запрещают другой CTA?). Составить таблицу конфликтов.
4. **Порядок включения**: что подключать сначала (без порогов), что после набора аудитории, что после юр-решений владельца.
5. **Эффект масштаба**: где добавление механизма даёт маржу ~100% (тот же контент, новый источник) vs где требует новой работы.

## Обязательные блоки артефакта `MONETIZATION_STACKS.md`
1. **Матрица совместимости** (механизм × механизм): совместимо / конфликтует / требует проверки. Минимум 15×15 по ключевым механизмам из F. С указанием причины конфликта и источника.
2. **5–8 готовых стеков** — каждый с полным описанием:
   - Название стека и суть одной фразой.
   - Ниша/тип контента (из THEMES_MATRIX).
   - Площадки и порядок публикации (что куда первым, задержки, уникализация).
   - Слои дохода (перечислить все, с ожидаемой долей каждого в %).
   - Производство: сколько минут работы флота на ролик, какие шаги автоматизированы, где ручной слой (Klipni-правило «не чисто ИИ»).
   - Экономика: расчёт на 300к просм/мес (и на 1М просм/мес) — gross, комиссии, налоги, нетто ₽/мес.
   - Пороги и сроки: когда включается каждый слой.
   - Риски (юр/ToS/бан/демонетизация) и митигации.
   - Требуется ли решение владельца (эскалация) и какое именно.
3. **Сравнительная таблица стеков**: вход ₽/мес, дни до первой выручки, нетто при 300к просм, трудоёмкость ₽/час, автоматизируемость, риск-уровень, масштабируемость.
4. **Рекомендация company**: какой стек стартовым (с обоснованием), какой вторым, какой — после эскалаций. Формат: hypothesis → expected impact → confidence → cost → kill criterion → rollback.
5. **Дорожная карта наслоения**: Д0–14 / Д15–45 / Д46–90 / Д90+ — какие слои добавляются на каждом этапе и при каком триггере.
6. **«Что НЕ совмещаем и почему»** — явный список отвергнутых комбинаций с причиной (это важная часть: не строить кашу).
7. Пробелы `null` с планом проверки.

## Границы
- Это design/research-карта: ничего не запускать, не покупать, не публиковать.
- Не выдумывать ставки — брать из F/G/существующих артефактов, при отсутствии = null.
- Соблюдать анти-кашу: каждый стек должен быть реализуем текущим конвейером (autoclip + director/editor/qa + MPT + аватар) без новых профессий, либо явно помечать требуемую новую роль (триггер создания спецагента по ORG_MODEL.md).
- Красные/серые маршруты включать в стеки ТОЛЬКО с явной пометкой «требует письменного решения владельца» и указанием, какой именно риск принимается.
